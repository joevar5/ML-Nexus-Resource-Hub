## 1. Project Folder Structure and Actions

This section details what each directory in the workspace is responsible for, where key technologies like **Great Expectations** are integrated, and how to trigger executions within them.

### 1. `dags/` (Airflow Orchestration)
* **Purpose**: Houses the Directed Acyclic Graphs (DAGs) defining task orchestration logic, failure handling, and scheduled retry parameters.
* **Key Files**:
  * [ml_pipeline_dag.py](dags/ml_pipeline_dag.py): Coordinates the end-to-end training pipeline.
  * [retraining_dag.py](dags/retraining_dag.py): Triggers automated retraining if data drift is detected.
* **How to Execute**:
  1. Open the Apache Airflow web console at `http://localhost:8080` (log in with `admin` / `admin`).
  2. Toggle the desired DAG status to **Active**.
  3. Click **Play (Trigger DAG)** to manually initiate execution.

### 2. `dvc/` (Data Version Control & Infrastructure Stack)
* **Purpose**: Contains the DVC data versioning configurations, stage pipeline definitions, training params, and docker infrastructure services definition.
* **Key Files**:
  * [docker-compose.yml](dvc/docker-compose.yml): Manages container services (Postgres, MinIO, Redis, MLflow, Airflow).
  * [dvc.yaml](dvc/dvc.yaml): Defines DAG stages, dependencies, and expected outputs.
  * `params.yaml`: Central parameter configuration for DVC steps.
* **How to Execute**:
  * Start the service stack: `docker-compose -f dvc/docker-compose.yml up -d`
  * Run the DVC pipeline: `dvc repro`
  * Inspect the pipeline topology: `dvc dag`

### 3. `great_expectations/` (Data Quality Assurance)
* **Purpose**: Defines schema validations, data sanity tests, and data quality check gates to protect the model from training on corrupted data.
* **Where Great Expectations is used**:
  * **Within DVC Pipeline**: In [dvc.yaml](dvc/dvc.yaml#L42), the `validate` stage is run via the command line: `python -m great_expectations.cli.cli checkpoint run training_data_checkpoint`.
  * **Within Airflow Pipeline**: The `validate_with_great_expectations` task in [retraining_dag.py](dags/retraining_dag.py#L127) calls the DVC validate step using a `BashOperator`.
  * **Validation Assertions**: The file `expectations/training_data_suite.json` holds all data type checks and range assertions.
* **How to Execute**:
  * Run validations manually: `great_expectations checkpoint run training_data_checkpoint`
  * Build and view data validation HTML logs:
    ```bash
    great_expectations docs build
    # Open the generated report:
    open great_expectations/uncommitted/data_docs/local_site/index.html
    ```

### 4. `mlflow/` (Model Tracking & Registry Metadata)
* **Purpose**: Contains settings defining the workflow as a portable MLflow Project.
* **Key Files**:
  * [MLproject](mlflow/MLproject): Specifies Conda/Docker environments and runs entry points like `main`, `preprocess`, `evaluate`, and `tune`.
* **How to Execute**:
  Run pipeline entry points directly using the MLflow command-line tool:
  ```bash
  mlflow run mlflow/ -P num_epochs=10 -P learning_rate=0.001
  ```

### 5. `src/` (Python Pipeline Source Code)
* **Purpose**: Core functional Python modules executing raw data operations and deep learning training scripts.
* **Key Files**:
  * [data_ingestion.py](src/data_ingestion.py): Loads raw transactions.
  * [preprocessing.py](src/preprocessing.py): Prepares splits and features.
  * [training.py](src/training.py): Runs PyTorch model training and tracks epochs and models using MLflow.
  * [evaluation.py](src/evaluation.py): Tests models and exports ROC / Confusion matrix plots.
* **How to Execute**:
  Execute individual scripts from the root directory:
  ```bash
  python -m src.data_ingestion --output data/raw
  python -m src.preprocessing --input data/raw --output data/processed
  python -m src.training --train data/processed/train.parquet --output models/current
  ```

### 6. `tests/` (Unit & Integration Testing)
* **Purpose**: Holds integration testing scripts to make sure changes to the code do not break the preprocessing or model tracking setup.
* **Key Files**:
  * [test_pipeline.py](tests/test_pipeline.py): Integration tests.
* **How to Execute**:
  ```bash
  pytest tests/
  ```

## 2. Setup Virtual Environment

First, create a clean virtual environment and install the required dependencies:

```bash
# Create virtual environment
python3 -m venv venv
source venv/bin/activate

# Install requirements
pip install --upgrade pip
pip install -r src/requirements.txt
```

---

## 3. Start Infrastructure Services

Start the Docker Compose stack (the environment variables are pre-configured in `docker-compose.yml`, so no `.env` setup is required):

```bash
# Start Postgres, MinIO, Redis, Airflow, and MLflow
docker-compose -f dvc/docker-compose.yml up -d
```

Verify that all containers are healthy:
```bash
docker-compose -f dvc/docker-compose.yml ps
```

---

## 4. Initialize Apache Airflow

To initialize the Airflow metadata database and set up the admin credentials:

```bash
# Initialize database
docker-compose -f dvc/docker-compose.yml exec airflow-webserver airflow db init

# Create admin user
docker-compose -f dvc/docker-compose.yml exec airflow-webserver airflow users create \
    --username admin \
    --password admin \
    --firstname Admin \
    --lastname User \
    --role Admin \
    --email admin@example.com
```

---

## 5. Configure Storage Buckets

1. Open your browser and navigate to the MinIO Console at `http://localhost:9001`.
2. Login with credentials:
   - **Access Key**: `minioadmin`
   - **Secret Key**: `minioadmin`
3. Click on **Buckets** in the sidebar, then click **Create Bucket**.
4. Name the bucket `mlflow` and click **Create Bucket**. This is where MLflow will save trained model checkpoints and training plots.

## 6. Running the Pipeline via DVC

You can execute the pipeline locally using DVC (Data Version Control). Each stage will cache its outputs so that only modified components are re-run on subsequent executions.

```bash
# Ingest raw transaction data
dvc repro ingest

# Clean data, perform feature engineering, and split datasets
dvc repro preprocess

# Validate data quality using Great Expectations expectation suite
dvc repro validate

# Train the model and log parameters to MLflow
dvc repro train

# Evaluate the model on the test set and generate plots/metrics
dvc repro evaluate

# Alternatively, run the entire pipeline at once:
dvc repro
```

Verify the DVC pipeline topology:
```bash
dvc dag
```

---

## 7. Orchestrating the Pipeline via Airflow

Airflow automatically triggers or schedules DAG runs, passing information between tasks using XCom.

1. Open the Airflow Webserver UI at `http://localhost:8080`.
2. Login with the user you created (`admin`/`admin`).
3. Locate the DAGs:
   - **`ml_training_pipeline`**: The core end-to-end training pipeline.
   - **`model_retraining`**: Scheduled retraining trigger gated by data drift sensors and staging promotion thresholds.
4. Unpause the DAGs by toggle-switching them to **Active**, then click the **Play** button to trigger a manual run.

---

## 8. Viewing Experiment Tracking in MLflow

All training metrics, hyperparameters, dataset version tags, model registry versions, and evaluation plots are tracked in MLflow.

1. Navigate to the MLflow UI at `http://localhost:5000`.
2. Select your experiment from the left menu.
3. Click on any run to inspect:
   - **Parameters**: `learning_rate`, `n_estimators`, `max_depth`, `algorithm`, etc.
   - **Metrics**: `train_loss`, `train_accuracy`, `val_loss`, `val_accuracy`, etc.
   - **Artifacts**: confusion matrix heatmaps, ROC curves, and the registered model artifact binaries.
