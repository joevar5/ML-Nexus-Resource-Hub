## Project Overview

Build a comprehensive monitoring and alerting system for ML infrastructure covering application metrics, infrastructure health, model performance, and business KPIs. This project introduces production observability: logs, metrics, traces, alerting, and incident response.

### Real-World Context

Your ML systems are now in production (Projects 1-3), but you're flying blind without proper monitoring. When things break at 3 AM, you need to know immediately. When models drift, you need alerts. When infrastructure is stressed, you need visibility. Without a robust observability stack, teams struggle with:

- **Blind incidents** - "The API has been down for 40 minutes and nobody noticed"
- **Silent model degradation** - "Accuracy dropped from 92% to 78% over two weeks and we only found out from customer complaints"
- **No root cause** - "The system is slow but we don't know if it's the database, the model, or the network"
- **Alert fatigue** - "We get 500 alerts a day and ignore all of them"
- **No historical data** - "We can't tell if this latency spike is normal or unprecedented"

This project simulates building a production-grade observability stack that solves these problems, covering metrics collection, log aggregation, visualization, alerting, and ML-specific monitoring (drift, data quality, model performance).

## Technology Stack

### Core Technologies

| Component | Technology | Purpose |
|-----------|------------|---------|
| **Metrics Collection** | Prometheus 2.47+ | Time-series metrics storage and scraping |
| **Alerting** | Alertmanager 0.26+ | Alert routing, grouping, and notification |
| **Visualization** | Grafana 10.2+ | Dashboards and metrics visualization |
| **Log Storage** | Elasticsearch 8.11+ | Log aggregation, indexing, and search |
| **Log Processing** | Logstash 8.11+ | Log parsing, enrichment, and forwarding |
| **Log Visualization** | Kibana 8.11+ | Log search and visualization |
| **Log Shipping** | Filebeat 8.11+ | Lightweight log collection from nodes |
| **Infrastructure Metrics** | Node Exporter 1.6+ | CPU, memory, disk, network metrics |
| **App Instrumentation** | prometheus-client (Python) | Application-level metrics exposure |

### Why These Technologies?

- **Prometheus**: Industry standard for metrics collection (used by SoundCloud, DigitalOcean, GitLab)
- **Grafana**: Most popular open-source visualization platform with 60K+ GitHub stars
- **Elasticsearch (ELK Stack)**: De facto standard for log aggregation and search at scale
- **Alertmanager**: Native integration with Prometheus, powerful routing and grouping
- **Node Exporter**: Lightweight, official exporter for host-level metrics
- **Filebeat**: Efficient, reliable log shipping with backpressure handling

## Getting Started

### Prerequisites

Before starting this project, ensure you have:

- Completed Projects 1-3 (API Deployment, Kubernetes, ML Pipeline)
- Docker and Docker Compose installed
- Python 3.11+ installed
- Git installed
- Basic understanding of:
  - Linux system administration (CPU, memory, disk)
  - Web APIs and HTTP protocols
  - Time-series data concepts
  - Log management basics

### Execution Guide

For step-by-step instructions on starting the monitoring stack, configuring Prometheus scrape targets, creating Grafana dashboards, setting up alerting rules, and testing alerts, please refer to the dedicated [4.3-how-to-execute-this-solution.md](4.3-how-to-execute-this-solution.md) guide.

### Quick Start

1. **Navigate to project directory:**
   ```bash
   cd projects/project-04-monitoring-alerting/
   ```

2. **Copy environment configuration:**
   ```bash
   cp .env.example .env
   ```

3. **Start the monitoring stack with Docker Compose:**
   ```bash
   docker-compose up -d
   ```

4. **Verify services:**
   - Prometheus UI: http://localhost:9090
   - Alertmanager UI: http://localhost:9093
   - Grafana UI: http://localhost:3000 (admin/admin123)
   - Elasticsearch: http://localhost:9200
   - Kibana UI: http://localhost:5601
   - Node Exporter: http://localhost:9100/metrics
